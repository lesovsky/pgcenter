## Сессия A — широкий терминал (190×52)

### Шаг 2 — заморозка держится (критерии 1, 14)

1. Открыть `activity`, интервал обновления 1 с.
2. `tmux capture-pane -p > /tmp/a-0.txt`
3. `tmux send-keys -t pg016 Space`
4. Сразу снять `/tmp/a-1.txt`, подождать **≥60 с**, снять `/tmp/a-2.txt`.
5. `diff /tmp/a-1.txt /tmp/a-2.txt`

**PASS:** diff пуст; `[PAUSED]` виден в командной строке; **часы в шапке не изменились**.
**FAIL:** любое расхождение, включая только часы — замороженный кадр с тикающими часами это дефект,
ради которого задача 04 и делалась.

Затем — снятие паузы (критерий 14): `send-keys Space`, снять экран через один интервал обновления.
**PASS:** часы пошли, значения обновились, всплеска (аномально больших дельт) нет.

### Шаг 3a — кадр не подменяется свежим (критерий 3) ⏱

**Это самый важный шаг плана и его нельзя сокращать.** Хранилище, которое молча переписывается на
перерисовке, выглядит идеально на коротком интервале и ломается на длинном.

1. Экран с быстро меняющимися числами, запомнить/снять `/tmp/b-0.txt`.
2. `send-keys Space`.
3. **Ждать ≥3 минуты.**
4. `send-keys '['` — принудительная перерисовка.
5. Снять `/tmp/b-1.txt`, сравнить значения с `b-0`.

**PASS:** значения те же, что были в момент паузы.
**FAIL:** значения «догнали» реальность — кадр подменяется.

### Шаг 3 — работа с замороженным кадром (критерий 5)

На паузе по очереди, снимая экран после каждого: `/` + выражение + `Enter`, затем `\`, `[`, `]`, `↑`, `↓`.

```bash
tmux send-keys -t pg016 '/' ; tmux send-keys -t pg016 'postgres' Enter
tmux send-keys -t pg016 '\' ; tmux send-keys -t pg016 '[' ; tmux send-keys -t pg016 ']'
tmux send-keys -t pg016 Up  ; tmux send-keys -t pg016 Down
```

**PASS:** каждое даёт видимое изменение кадра, `[PAUSED]` на месте; после фильтра строк меньше.
**FAIL:** экран не реагирует, или пауза слетела.

### Шаг 9 — расширение колонки (критерий 17, дубль к юнит-тесту)

На замороженном кадре сузить колонку `↓` до появления `~`, затем расширить `↑`.
**PASS:** значение показано полностью, остаточного `~` нет.

### Шаг 4 — пейджер и возврат (критерии 12, 16)

`send-keys l` → выйти из пейджера (`q`) → снять экран.
**PASS:** тот же замороженный кадр, экран **не пустой**, `[PAUSED]` на месте.

### Шаг 7c + 7f — справка и пробел в диалоге (критерии 9, 11, 20)

```bash
tmux send-keys -t pg016 h          # справка на паузе
tmux capture-pane -p > /tmp/help.txt
tmux send-keys -t pg016 Escape
tmux send-keys -t pg016 '/' ; tmux send-keys -t pg016 'a b' ; tmux send-keys -t pg016 Escape
```

**PASS:**
- справка открылась и закрылась, паузу не сняв;
- в `/tmp/help.txt` есть строка про `Space` с перечнем снимающих действий (критерий 11 — это шаг 7f);
- пробел в поле ввода **вводится как символ** и паузу не переключает (критерий 20 — единственная
  проверка того, что биндинг `Space` ограничен контекстом `sysstat`; юнит-тестами он не покрывается
  by construction, `keys` — локальный слайс).

### Шаг 7a — меню открывается, не снимая паузу (критерий 7)

`send-keys D`, затем `Escape`; то же с `A`.
**PASS:** `[PAUSED]` на месте, кадр не изменился.

### Шаг 7 — все снимающие клавиши (критерий 6)

По очереди, **восстанавливая паузу между шагами**:
`←`, `→`, `<`, `,`, `I`, `A`, `t`, `D`+`Enter`, `X`+`Enter`, `P`+`Enter`, `J`+`Enter`, `S`, `v`, `B`, `N`, `F`, `L`.

**PASS:** каждая снимает паузу, первый кадр обычный, без всплеска значений.

**Важное правило:** если какая-то клавиша паузу **не** сняла — это FAIL, **кроме** случая, когда в
командной строке появилось сообщение о досрочном возврате (например `S` на удалённом подключении,
`L` при недоступном логе). Отсутствие такого сообщения при неснятой паузе — дефект, а не исключение.

### Шаг 7e — round-trip через редактор (критерии 7, 12, 16) ⚠

Единственная проверка половины «or editor» и единственная проверка исключения `E`.

1. Поставить паузу.
2. `send-keys E`, выбрать файл конфигурации.
3. Выйти из редактора (`vi`, если `$EDITOR` не задан — `:q`).
4. Снять экран.

**PASS:** и замороженный кадр, и `[PAUSED]` вернулись; пауза **сохранилась** (в отличие от прочих
пунктов меню).
**Оговорка:** `editPgConfig` имеет собственную защиту для удалённых хостов
(`top/pgconfig.go`, «Edit config is not supported for remote hosts»). Если появилось это сообщение —
шаг не выполнился, критерии 12/16 в части «редактор» остаются NOT VERIFIABLE. Тогда стоит повторить
на локальном подключении (`-h 127.0.0.1`), иначе половина двух критериев остаётся незакрытой.

### Шаг 7d — панель логов (критерий 10) ⚠

**Категорически нельзя закрывать юнит-тестами** — задача 10 называет этот критерий как пример.

1. Открыть панель логов `L` (нужен `logging_collector = on` и доступный файл лога).
2. Поставить паузу.
3. Писать в лог: `psql -c 'SELECT pg_reload_conf()'` или заведомо ошибочный запрос.
4. Снять экран — новых строк быть не должно.
5. Уйти в пейджер `l`, выйти, снова снять экран.

**PASS:** пока пауза активна, новых строк нет; после возврата из пейджера панель показывает **те же
строки**, а не пустоту.
**Если `L` не открылась** (лог недоступен, нет прав) — критерий 10 помечается NOT VERIFIABLE
с причиной. Никогда не PASS «по аналогии».

### Шаг 7b — ошибка во время паузы (критерий 8)

1. Поставить паузу.
2. Остановить кластер (`pg_ctlcluster N main stop`).
3. Подождать несколько интервалов, снять экран — **изображение не меняется**.
4. `send-keys Space` — снять паузу.

**PASS:** на паузе картинка неподвижна; сообщение об ошибке появляется на первом кадре после снятия.
**Не забыть поднять кластер обратно** (см. уборку).

### Шаг 8 — `Space` до первого кадра (критерии 15, 16)

1. Запустить pgcenter и **немедленно** отправить `Space` (до появления первого кадра).
2. Снять экран.
3. Уйти в пейджер `l`, выйти, снять снова.

**PASS:** `[PAUSED]` появился, экран **пустой**; после возврата из пейджера маркер на месте, экран
по-прежнему пуст (перерисовывать нечего — это норма, а не дефект). После снятия паузы приходит
обычный первый кадр.

### Шаг 5 — изменение размера во время паузы (критерий 13)

```bash
tmux resize-window -t pg016 -x 60 -y 52 ; tmux capture-pane -p > /tmp/r60.txt
tmux resize-window -t pg016 -x 190 -y 52 ; tmux capture-pane -p > /tmp/r190.txt
```

**PASS:** после сужения колонок меньше, после расширения — больше; стрелка `›` пропадает с той
стороны, где скрытых колонок не осталось. Всё это **не снимая паузу**.

### Шаг 11 — прогон по всей раскладке (критерий 4)

Худший сценарий отказа фичи — зависание UI, автоматического харнесса для него нет.

На паузе отправить по очереди каждую клавишу основной раскладки, между нажатиями снимая экран.
**PASS:** интерфейс отвечает на каждое нажатие, зависаний нет.
**FAIL:** любое нажатие, после которого экран перестал отвечать — это самый серьёзный класс дефекта
в фиче, при нём вердикт NEEDS WORK независимо от остального.

## Шаг 10 — сравнение с master

Прогнать `/tmp/pgcenter-master` по шагам 2–9 в тех же условиях.
**Цель:** каждое расхождение классифицировать как «внесено фичей» или «было и раньше».
Полезно как минимум для: поведения `S`/`L` на этом стенде, ширины колонок, поведения пейджера.

## Что НЕ считать дефектом

- Пустой экран после `Space`, нажатого до первого кадра, — включая возврат из пейджера.
- Более раннее обрезание подсказки в диалогах на паузе (маркер занимает ~8 символов).
- `S` на удалённом подключении и `L` при недоступном логе не снимают паузу — **при условии**, что
  в командной строке появилось сообщение о досрочном возврате.
- Пункт меню конфигов `E` не снимает паузу — это оговорённое исключение.
- Панель логов не пополняется на паузе — это и есть проверяемое поведение.
